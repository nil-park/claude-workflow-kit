# 작업 단계

네 단계로 이루어져 있다.

1. 작업 단위 확정
2. 설계
3. 구현
4. 보고

**내가 명시적으로 구현을 지시하기 전에는 구현을 시작하거나 "구현을 시작할까요?"라고 묻지 마라.**

## 1. 작업 단위 확정

- 내가 이슈 번호나 Jira 이슈 키를 주면 그것이 작업 단위다.
- 다음 내용을 리포지토리의 임시 디렉토리에 정리한 뒤 확인받는다.
  - 예상 변경 범위와 분량
  - 내 지시에 명시되지 않았지만 이행에 필요한 전제와 가정
  - 규모를 바탕으로 별도 설계 단계가 필요한지 여부
- **내가 명시적으로 "설계만" 또는 "구현만"이라고 지정하지 않는 한, PR은 설계와 구현을 모두 포함한다.**
- 브랜치를 만들어 push한다. **이 단계에서 구현 코드를 한 줄도 쓰지 않는다.**
- 브랜치 이름은 `<타입>/<이슈번호>-<슬러그>`로 짓는다(예: `chore/47-add-user-ssh-key`). 이슈가 없으면 번호를 생략한다.
- **origin의 기본 브랜치(main/master)를 먼저 확인한다.** 그것이 PR 대상 브랜치다.

## 2. 설계

- 스펙 문서는 리포지토리의 문서 디렉터리에 쓴다.
  - 리포지토리에 명시된 문서 규약이 있다면 철저히 지킨다.
  - 문서 규약이 없다면 기존 문서들을 살펴 컨벤션을 파악한 뒤 임시 디렉토리에 요약해서 확인받는다.
- 이슈 등 레퍼런스로 삼을 문서가 이미 모든 맥락을 빠짐없이 설명하고 있으면 설계 문서 수정과 구현 단계를 동시에 진행할 수도 있다. 단, 나에게 먼저 확인받는다.
- from scratch로 시작할 경우 설계가 확정되기 전에는 구현을 시작하지 않는다. 나와의 대화를 통해 큰 줄기를 잡고, 세부 내용은 네가 초안을 작성한다.
- 구현 단계로 들어가면 명시적인 지시 없이 설계 문서를 고치지 않는다. 불가피한 경우 마크다운 문서로 써서 나에게 보고하되, 세줄 요약이 불가능하면 설계 자체에 문제가 있는 것이므로 설계 단계로 돌아가야 한다.
- work-cycle 리뷰에서 "현재 코드와 설계가 어긋난 상태"가 지적되더라도, 아직 구현 전이면 정상이다. 이를 근거로 PR 범위를 설계 전용으로 재해석하지 않는다.

## 3. 구현

- 작업 단위를 잘게 쪼개서 커밋한다.
- 커밋 전에 리포지토리내 가이드에 따라 Linter와 Formatter, 유닛테스트 등을 실행한다.

## 4. 보고

- PR 제목과 본문에 드리프트가 없는지 여부를 체크해서 개정 후에 완성본을 제시한다.
- 내가 명시적으로 지시하거나 설계에 기록하지 않은 내용 중 임의로 가정한 것이 있으면 보고한다.
- 설계 단계에서 예상하지 못한 것 때문에 실제 구현이 설계와 차이가 있으면 보고한다.
- 보고할 항목이 3개 이상이면 리포지토리의 임시 디렉토리에 마크다운 문서로 써서 보고하되 두괄식으로 내용을 요약한다.
- PR을 Ready로 전환하되, **머지는 검토 후 내가 한다.**

# GitHub PR

- **PR 제목과 본문은 구현까지 완료된 최종 결과를 기준으로 작성한다.**
  - 설계 단계에서 draft를 열더라도 "설계 문서 추가", "설계 단계" 따위로 범위를 설계에만 한정하지 않는다.
- **커밋이 없으면 PR이 열리지 않는다.**
  - draft PR은 2단계의 첫 커밋과 함께 연다.
  - 스펙 문서를 생략하기로 했으면 3단계 첫 커밋에서 연다.
  - 이것 때문에 빈 커밋을 만들지는 않는다.

```
gh pr create --base "<origin 기본 브랜치>" --draft -a @me \
  -t "제목" --body-file <본문 파일>
```

- 본문 수정은 `gh pr edit --body-file <경로>`, Ready 전환은 `gh pr ready`.

# 본문 작성 규약

- 본문에 무엇을 넣고 뺄지는 리포지토리 규약을 확인해 준수한다.
- 이슈 번호나 Jira 키를 개별 커밋 메시지에는 넣지 않는다. 기본 브랜치에 직접 커밋할 때만 커밋 메시지에 넣는다.
- 본문은 파일로 쓴다. 멀티라인 텍스트를 명령줄에 직접 붙여 넣으면 escape 실수가 생기기 쉬우므로, `--body-file <경로>`로 파일 경로를 넘긴다.
