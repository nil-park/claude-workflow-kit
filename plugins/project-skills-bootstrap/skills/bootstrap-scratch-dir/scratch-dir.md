## 두 스크래치 공간

커밋하지 않는 작업 파일은 성격에 따라 두 곳 중 하나에 둔다.

### 하네스 스크래치패드

스크립트 실행이나 CLI 인자 전달에 사용할 수 있는 실제 임시 저장소다. 작업 도중 소비되고, **사용자가 직접 볼 필요가 없는 것**을 저장한다.

- 임시 스크립트
- `gh`/`glab`에 넘길 PR/MR/이슈 본문 파일
- 작업 사이클 라운드마다 기록하는 중간 리뷰 문서
- 멀티 에이전트 실행 시 에이전트 간에 공유하는 파일
- 그 밖의 중간 산출물

PR/MR 본문처럼 여러 줄 텍스트는 파일에 쓰고 경로로 넘긴다(`--body-file <경로>` /
`-d "$(cat <경로>)"`). 명령줄에 직접 붙이면 Bash와 PowerShell 문법이 섞여 `@` 줄이
남거나 백틱이 두 배로 늘어난 채 올라간다. 둘 다 실패하지 않고 통과해서 게시된 뒤에야
보인다.

#### 경로 결정

1. 하네스가 경로를 지정하면 그것을 사용한다.
2. 없으면 OS 임시 디렉터리에 아래 규칙으로 생성한다.
   `<OS-temp>/agent/<project-slug>/<timestamp>/`
   - `project-slug`: 리포 루트 디렉터리 이름, 경로 구분자는 `-`로 치환
   - `timestamp`: 세션 시작 시점의 `YYYYMMDD-HHMMSS`

#### 실제 임시 저장소에 접근할 수 없는 환경

이 섹션의 용도를 수행할 수 없다. `{{scratch_dir}}` 디렉터리만 활용한다.

### {{scratch_dir}} 디렉터리

`<repo-root>/{{scratch_dir}}/`는 프로젝트 로컬 스크래치다. **사용자가 열람하거나 장기간 참조하는 것**을 저장한다.

- 레퍼런스 리포지토리 클론: 작업에 참고하는 외부 리포를 여기 클론한다
- 작업 사이클 최종 보고서: 사용자가 확인하는 최종 요약본
- 도메인 가정: 작업 중 드러난 전제를 사용자에게 확인하고 승인을 받기 위해 작성한다
- 이후에 다시 볼 메모

파일 이름은 고유하고 뜻이 드러나는 kebab-case로 짓는다. 고정된 이름은 병렬 세션이
덮어쓰므로 쓰지 않는다. 브랜치나 주제를 이름에 넣는다. 예를 들면 `review-<번호>.md`,
`followup-<주제>.md`.

한 작업이 파일을 여럿 만들면 그 작업 이름의 하위 디렉터리에 모은다.

**리포지토리 밖의 파일을 고치는 작업에는 `{{scratch_dir}}/`가 없다.** 원본을 그 자리에서 고치고
롤백용 사본을 옆에 둔다. 사본을 다른 곳에 두면 도구가 실제로 읽는 파일이 아니라서 고친
것이 먹히는지 확인할 수 없다. 확장자는 `<원본이름>.bak` 순서로 붙인다. `foo.bak.md`처럼
두면 `~/.claude/agents/`같이 `*.md`를 전부 긁는 자리에서 사본까지 설정으로 읽힌다.
