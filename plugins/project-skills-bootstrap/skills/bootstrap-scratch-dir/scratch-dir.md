## 두 스크래치 공간

커밋하지 않는 작업 파일은 성격에 따라 아래 두 디렉터리 중 한 곳에 저장한다.

### 하네스 스크래치패드

- 하네스 스크래치패드는 리포지토리 밖에 있는 임시 디렉터리다.
  - 스크립트를 실행하거나 CLI 명령에 파일을 넘길 때 이 경로를 그대로 지정할 수 있다.
- 작업 도중에만 참조하고 **사용자가 직접 볼 필요가 없는 파일**은 이 디렉터리에 만든다.
  - 임시 스크립트
  - `gh`/`glab`에 넘길 PR/MR/이슈 본문 파일
  - `work-cycle`의 리뷰 라운드마다 남기는 중간 기록
  - 여러 에이전트를 함께 실행할 때 에이전트끼리 공유하는 파일
  - 그 밖의 중간 산출물
- PR/MR 본문처럼 여러 줄 텍스트는 파일에 쓰고, 명령에는 그 파일을 넘긴다.
  - `gh`: `--body-file <경로>`
  - `glab`: `-d "$(cat <경로>)"`
- 여러 줄 텍스트를 명령줄에 직접 붙여 넣으면 Bash와 PowerShell 문법이 섞인다.
  - 본문에 `@` 줄이 남거나 백틱이 두 배로 늘어난 채 게시된다.
  - 명령은 오류 없이 끝나므로, 게시된 본문을 확인하기 전에는 문제를 알 수 없다.

#### 경로 결정

1. 하네스가 경로를 지정하면 그 경로를 사용한다.
2. 하네스가 경로를 지정하지 않으면 다음 경로에 디렉터리를 만든다.
   - `<OS-temp>/agent/<project-slug>/<timestamp>/`
   - `project-slug`: 리포지토리 루트의 절대 경로에서 경로 구분자와 `:`를 `-`로 바꾼 값(예: `C:\Git\my-repo` → `C--Git-my-repo`)
   - `timestamp`: 세션을 시작한 시각을 `YYYYMMDD-HHMMSS` 형식으로 적은 값

#### 스크래치패드에 접근할 수 없는 환경

- 하네스 스크래치패드용 파일도 모두 `{{scratch_dir}}` 디렉터리 안에 만든다.

### {{scratch_dir}} 디렉터리

- `<repo-root>/{{scratch_dir}}/`는 리포지토리 안에 있는 스크래치 디렉터리다.
- **사용자가 직접 열어 보거나 오래 참조할 파일**은 이 디렉터리에 보관한다.
  - 작업에 참고할 외부 리포지토리의 클론
  - `work-cycle`을 마치고 사용자에게 제출하는 최종 보고서
  - 작업 중에 드러난 도메인 전제를 사용자에게 승인받으려고 정리한 문서
  - 나중에 다시 볼 메모
- 파일 이름은 뜻이 드러나는 kebab-case로 짓는다.
  - 병렬 세션이 같은 파일을 덮어쓸 수 있으므로 고정된 이름은 사용하지 않는다.
  - 이름에 브랜치나 주제를 넣는다(예: `review-<번호>.md`, `followup-<주제>.md`).
- 한 작업에서 파일이 여럿 생기면, 작업 이름의 하위 디렉터리에 모은다.
- **리포지토리 밖의 파일을 고치는 작업에는 `{{scratch_dir}}/`가 없다.**
  - 원본은 그 자리에서 고치되, 먼저 같은 디렉터리에 롤백용 사본을 만든다.
  - 원본을 다른 곳에 복사해서 고치면 도구가 읽는 파일은 바뀌지 않으므로, 수정이 반영되는지 확인할 수 없다.
  - 사본 이름은 `<원본 이름>.bak` 형식으로 짓는다.
    - `foo.bak.md`로 이름을 지으면, `~/.claude/agents/`의 `*.md`를 모두 읽어 들이는 Claude Code 같은 도구가 사본까지 설정으로 인식한다.
