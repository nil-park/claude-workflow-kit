# mem4j

`mem4j`는 여러 에이전트가 함께 읽고 쓰는 공유 기억을 Neo4j 그래프에 저장하는 컴포넌트다.

## 구성 요소

- 데이터베이스: Neo4j
  - 여러 사용자가 데이터베이스 하나를 함께 사용한다.
  - 지침의 원본(SoT)은 그래프이며, 모든 쓰기는 이 문서의 규칙을 검사하는 명령을 거친다.
- 임베딩 모델: Gemini Embedding 2 (GCP Vertex AI `global` 엔드포인트)
  - 출력 차원: 768
  - 인증: GCP 서비스 계정 JSON(포함된 `project_id` 사용)

## 노드 레이블

- 두 계열은 노드 하나에 함께 붙일 수 있는 레이블의 조합으로 구분한다.
  - 지침 계열 레이블(`Instruction`, `Reminder`, `Scope`)은 서로 배타적이다(예: 한 노드가 `Instruction`과 `Scope`를 동시에 가질 수 없다).
  - 백데이터 계열 레이블(`Entity`, `Statement`, `Event`)은 서로 배타적이지 않다.
  - 서로 다른 계열의 레이블은 노드 하나에 함께 붙일 수 있다(예: `Instruction`과 `Statement`, `Scope`와 `Entity`).
- 지침 계열: 에이전트가 어떻게 행동해야 하는지 지시한다.
  - `Instruction`: 상시 지침 노드
  - `Reminder`: `Instruction`의 변형으로, 조건부로 주입되는 instant 지침 노드
  - `Scope`: 스코프 노드
- 백데이터 계열: 작업 확인에 쓰이는 사실, 상태, 이력을 기록한다.
  - `Entity`: 대상이나 개체를 나타내는 노드
  - `Statement`: 사실이나 상태를 서술하는 노드
  - `Event`: `Statement`의 변형으로, 특정 시점에 일어난 일을 기록하는 이력 노드
- `Scope`와 `Entity`는 서로 다른 역할을 맡는 허브 레이블이다.
  - `Scope`: 세션 시작 시 활성 스코프 후보로 노출되며, `Instruction`과 `Reminder`가 연결되는 허브(작은 집합으로 유지)
  - `Entity`: `Statement`와 `Event`, 대상 간 관계가 연결되는 허브(개수 제한 없이 확장)
  - 둘 모두에 해당하는 대상(예: 사용자, 리포지토리, PC 환경)은 노드를 복제하지 않고 하나에 `Entity`와 `Scope` 레이블을 함께 붙인다.
  - 이 이중 레이블 노드가 두 계열을 연결하며, 활성 `Scope`에서 `Entity` 탐색을 시작하는 진입점이 된다.

## 노드 프로퍼티

- 허브 노드(`Scope`, `Entity`)는 `name`으로 식별하고, `name`이 없는 리프 노드(`Instruction`, `Reminder`, `Statement`, `Event`)는 `key`와 `title`을 가진다.
- `description`은 임베딩 입력이자 식별용 설명이고, `body`는 본문이다.
  - `Instruction`은 `description`이 없다.
  - `Scope`는 임베딩 없이 대화에서 스코프를 식별하는 설명을 적는다.
  - `Entity`는 대상을 식별하는 핵심 정보와 별칭을 적는다.
  - `Reminder`는 대화 중간에 주입되는 시점을 적는다.
  - `Statement`와 `Event`는 임베딩 검색에 쓰이는 핵심 서술을 적으며, 본문이 짧으면 본문을 그대로 쓸 수 있다.

| 프로퍼티                           | 대상 노드                                           | 의미                                                                                                            | 없을 때                                   |
| ---------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `name` (string)                    | `Scope`, `Entity`                                   | 허브 노드를 식별하는 고유 이름                                                                                  | 필수                                      |
| `key` (string)                     | `Instruction`, `Reminder`, `Statement`, `Event`     | 리프 노드를 식별하는 고유 키(`Reminder`, `Statement`, `Event`는 생략 시 10자리 소문자 영숫자 랜덤 ID 자동 발급) | 필수                                      |
| `title` (string)                   | `Instruction`, `Reminder`, `Statement`, `Event`     | 리프 노드를 식별하는 짧은 이름(예: "작성-리뷰 사이클")                                                          | 필수                                      |
| `description` (string)             | `Scope`, `Entity`, `Reminder`, `Statement`, `Event` | 노드를 식별하거나 임베딩 검색에 사용하는 설명                                                                   | 필수                                      |
| `body` (string)                    | `Instruction`, `Reminder`, `Statement`, `Event`     | 지침이나 사실, 이력의 본문                                                                                      | 필수                                      |
| `occurredAt` (string)              | `Event`                                             | 사건이 일어난 시각 또는 날짜(UTC ISO 8601)                                                                      | 필수                                      |
| `embedding` (list\<float\>)        | `Entity`, `Reminder`, `Statement`, `Event`          | `description`을 Gemini Embedding 2로 변환한 768차원 벡터                                                        | 필수                                      |
| `disableModelInvocation` (boolean) | 업무 스코프 `Scope`                                 | `true`면 에이전트가 스스로 활성화할 수 없고 사용자가 명시적으로 호출할 때만 활성화된다(예: `duo-session` 스킬). | `false`와 같음(에이전트 자율 활성화 허용) |
| `confirmed` (boolean)              | `Instruction`, `Reminder`, `Statement`, `Event`     | `true`면 사용자가 확인한 노드(사용자가 직접 작성한 내용 포함)이다.                                              | `false`와 같음(AI 추측)                   |

## 지침 스코프

- `mem4j`는 AI 에이전트 지침을 저장한다.
- 각 지침은 하나 이상의 스코프에 종속된다.
- 스코프는 고정된 목록이 없으며, 에이전트가 필요에 따라 스스로 판단해 생성한다.
  - 아래 표는 스코프의 예시다.

| 스코프               | 적용 범위                                                                       |
| -------------------- | ------------------------------------------------------------------------------- |
| 조직에 종속됨        | 특정 조직에 속한 모든 사용자                                                    |
| 사용자에 종속됨      | 특정 사용자                                                                     |
| PC 환경에 종속됨     | 특정 PC 환경(사용자 계정, 호스트, 셸 등. 예: `kwang@NilPark-A520M-K`, Git Bash) |
| 리포지토리에 종속됨  | 특정 리포지토리                                                                 |
| 업무 스코프에 종속됨 | 수행하는 업무의 종류                                                            |

- 모든 지침은 조직 스코프와 사용자 스코프 가운데 적어도 하나에 종속된다.
- 사용자는 조직에 소속될 수 있다.
- 스코프는 서로 겹칠 수 있다.
  - 예를 들어 지침 하나가 특정 리포지토리와 특정 PC 환경에 함께 종속된다.

## 지침 종류

- 지침은 컨텍스트 압축 뒤에 원문을 복원하는지 여부에 따라 두 종류로 나뉜다.
  - 상시 지침(`Instruction`): 세션의 스코프 교집합으로 자동 주입되어 세션 동안 유지되며, 압축 뒤에 원문이 복원된다.
  - instant 지침(`Reminder`): 활성 스코프 교집합 안에서 `description` 임베딩의 코사인 유사도 매칭으로 대화 중간에 주입되며, 압축 뒤에 원문이 복원되지 않는다.
    - 예를 들어 사용자가 "커밋해줘"라고 요청하면 "커밋 메시지는 영어로 쓴다"가 전달된다.
- 두 종류 모두 같은 스코프 규칙에 따라 스코프에 종속된다.

## 그래프 표현

- `Instruction`과 `Reminder`는 자신이 종속되는 하나 이상의 `Scope`와 1-hop 관계로 직접 연결된다.
  - 여러 `Scope`와 연결되면 연결된 스코프의 교집합에 종속된다.
  - `Instruction`이나 `Reminder` 노드끼리는 관계를 만들지 않는다.
- `Statement`와 `Event`는 자신이 서술하는 하나 이상의 `Entity`와 1-hop 관계로 직접 연결된다.
  - `Statement`나 `Event` 노드끼리는 관계를 만들지 않는다.
  - 대상 사이의 관계는 `Statement` 본문에 적지 않고 `Entity` 사이의 관계(relationship)로 표현한다.
- `Scope` 노드끼리와 `Entity` 노드끼리는 관계로 연결할 수 있다.
  - `Scope` 간 연결은 소속이나 플랫폼처럼 함께 활성화되는 연관 스코프 구조를 표현한다(예: 사용자와 조직, 리포지토리와 GitHub).
  - `Entity` 간 연결은 의존성, 소유, 연동 같은 대상 사이의 다단계 관계를 표현한다.
- 지침 단위는 문장 순서를 바꾸면 의미가 깨지는 최소 묶음이며, 단위마다 단독으로 완결된다.
  - 병합은 순서에 의존하지 않고 스코프가 일치하는 단위를 모두 모은다.
  - 내용이 대부분 비슷한 단위를 별도로 작성할 수 있다(예: `gh`/`glab`과 PR/MR만 다른 GitHub과 GitLab 절차 단위).

## 조회와 탐색

- 에이전트는 훅을 통한 자동 주입과 작업 도중 직접 수행하는 능동 탐색 두 경로로 그래프를 조회한다.
  - 자동 주입: 세션 시작 시 `Instruction`을, 프롬프트 제출 시 `Reminder`를 훅으로 주입한다.
  - 능동 탐색: 에이전트가 `Scope` 간 연결로 연관 스코프를 찾고, `Entity` 간 연결을 따라가며 1-hop으로 연결된 `Statement`와 `Event`를 조회한다.
- 의미 검색은 `Entity`, `Reminder`, `Statement`, `Event`의 `description` 임베딩 코사인 유사도로 수행한다.
- 능동 탐색은 CLI 탐색 명령과 읽기 전용 Cypher 쿼리로 제공한다.

## 지침 작성과 수정

- `Instruction`을 작성하거나 수정할 때에는 연결된 스코프 조합으로 병합한 전체 지침이 깨지지 않는지 확인한다.
  - 해당 `Instruction`이 포함되는 스코프 조합마다 병합 결과를 조회해, 다른 지침과 충돌하거나 문맥이 어긋나지 않는지 점검한다.
- `Reminder`를 작성하거나 수정할 때에는 프롬프트 임베딩이 잘 매칭되는지와 조건부 instant 지침으로 적절한지를 함께 판단한다.
  - `description`에는 사용자 프롬프트에 작업 의도가 드러나는 구체적인 시점을 적는다.
  - 셸 세부 문법처럼 사용자 프롬프트에 나타나지 않는 조건은 `Reminder`로 만들지 않는다.
  - 세션 동안 항상 지켜야 하는 규칙은 상시 지침(`Instruction`)으로 작성한다.
  - 도구 호출 시점에 검사해야 하는 규칙은 `Reminder` 대신 훅이나 상시 지침으로 처리한다.

## 자가 정정

- 기억을 사용하는 에이전트가 직접 그래프의 오류를 정정하고 유지한다.
- 병합된 지침이 현재 상황과 맞지 않을 때 정정한다.
  - 잘못된 지침이 포함되었거나 필요한 지침이 누락된 경우, 또는 사용자가 에이전트를 교정한 경우에 실행한다.
- 정정 대상
  - 대화에서 스코프를 잘 식별하지 못하는 `Scope` 설명 수정
  - 같은 의미를 가진 두 스코프 병합
  - 잘못된 스코프에 연결된 지침 이동
  - 틀린 지침 본문 수정
- 에이전트는 노드를 직접 수정하며, 변경 이력은 남기지 않는다.
