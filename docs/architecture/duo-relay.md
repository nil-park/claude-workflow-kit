# duo-relay

duo-relay는 서로 다른 터미널에서 실행 중인 대화형 CLI 세션 두 개가 메시지를 주고받게 하는 CLI다.

## 기능 요구사항

| ID    | 요구사항                   | 내용                                                                               |
| ----- | -------------------------- | ---------------------------------------------------------------------------------- |
| FR-01 | 대화형 TUI 유지            | 두 세션은 비대화형 모드로 바뀌지 않고, 사용자가 보는 대화형 화면을 유지한다        |
| FR-02 | 유휴 상태 자동 트리거      | 메시지가 도착하면 입력을 기다리던 세션이 키 입력 없이 새 턴을 시작한다             |
| FR-03 | 이기종 세션 간 텍스트 교환 | CLI가 자체 세션 간 통신 기능을 제공하는지와 관계없이 두 세션이 메시지를 주고받는다 |
| FR-04 | 사용자 입력 우선권 보장    | 메시지를 중계하는 동안에도 사용자는 언제든 직접 입력해 세션을 제어한다             |

## 대상과 환경

- 사용자: 나란히 띄운 터미널 두 개를 보면서, 필요할 때 직접 개입하는 개발자
- 세션: 각 터미널의 대화형 TUI에서 실행 중인 에이전트 CLI 세션
  - 두 세션의 CLI 종류는 같아도 되고 달라도 된다.
- 실행 환경: 같은 호스트에 있는 터미널 창 두 개

## 유스케이스

### UC-1: 두 터미널에 진행 상황 표시

- 시점: 두 세션이 메시지를 처리하거나 응답을 만들 때
- 동작
  - 사고 과정과 입출력은 백그라운드 호출에 가려지지 않고 각 터미널에 그대로 출력된다.
  - 사용자는 두 화면에서 번갈아 일어나는 작업을 함께 지켜본다.

### UC-2: 입력을 기다리는 세션의 자동 기상

- 시점: 입력을 기다리는 세션에 상대 세션의 메시지가 도착할 때
- 동작
  - 기다리던 세션은 사용자가 키를 누르지 않아도 바로 실행을 시작한다.
  - 도착한 메시지는 그 세션의 새 턴 입력으로 들어간다.

### UC-3: 서로 다른 CLI 세션 사이의 메시지 중계

- 시점: 서로 다른 CLI의 두 세션이 리뷰 요청이나 회신을 주고받을 때
- 동작
  - 두 CLI가 함께 쓰는 세션 간 통신 기능이 없어도, 텍스트를 빠짐없이 상대 세션에 전달한다.
  - 전송에 실패하거나 지연되면 사용자가 보는 터미널에 상태를 표시한다.
