# neo4j-memory

`neo4j-memory`는 여러 에이전트가 함께 읽고 쓰는 공유 기억을 Neo4j 그래프에 저장하는 컴포넌트다.

## 구성 요소

- 데이터베이스: Neo4j
  - 여러 사용자가 데이터베이스 하나를 함께 사용한다.
- 임베딩 모델: Gemini Embedding 2 (GCP Agent Platform)
  - 출력 차원: 768

## 노드 레이블

- 두 계열은 노드 하나에 함께 붙일 수 있는 레이블의 조합으로 구분한다.
  - 지침 계열 레이블(`Instruction`, `Reminder`, `Scope`)은 서로 배타적이다(예: 한 노드가 `Instruction`과 `Scope`를 동시에 가질 수 없다).
  - 백데이터 계열의 `Entity`와 `Statement`는 서로 배타적이지 않다.
  - 서로 다른 계열의 레이블은 노드 하나에 함께 붙일 수 있다(예: `Instruction`과 `Statement`, `Scope`와 `Entity`).
- 지침 계열: 에이전트가 어떻게 행동해야 하는지 지시한다.
  - `Instruction`: 상시 지침 노드
  - `Reminder`: instant 지침 노드
  - `Scope`: 스코프 노드
- 백데이터 계열: 작업 확인에 쓰이는 사실과 상태를 기록한다.
  - `Entity`: 대상이나 개체를 나타내는 노드
  - `Statement`: 사실이나 상태를 서술하는 노드
- `Entity`가 스코프에도 해당하면 노드 하나에 `Entity`와 `Scope` 레이블을 함께 붙인다(예: 사용자).
  - 이 이중 레이블 노드가 두 계열을 연결한다.

## 노드 프로퍼티

- `Scope` 노드와 `Reminder` 노드는 짧은 설명(description)을 가지며, `Instruction` 노드는 설명이 없다.
  - `Scope` 설명에는 대화에서 식별할 수 있는 스코프의 내용을 적는다.
  - `Reminder` 설명에는 대화 중간에 주입되는 시점을 기록한다.

| 프로퍼티                           | 대상 노드                 | 의미                                                                                                            | 없을 때                                   |
| ---------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `disableModelInvocation` (boolean) | 업무 스코프 `Scope`       | `true`면 에이전트가 스스로 활성화할 수 없고 사용자가 명시적으로 호출할 때만 활성화된다(예: `duo-session` 스킬). | `false`와 같음(에이전트 자율 활성화 허용) |
| `locked` (boolean)                 | 모든 노드                 | `true`면 에이전트가 수정하거나 삭제(소프트 삭제 포함)할 수 없고 사용자만 변경할 수 있다.                        | `false`와 같음(에이전트 수정과 삭제 가능) |
| `confirmed` (boolean)              | `Instruction`, `Reminder` | `true`면 사용자가 확인한 지침(사용자가 직접 작성한 지침 포함)이다.                                              | `false`와 같음(AI 추측)                   |
| `deletedAt` (DATETIME)             | 모든 노드                 | 값이 있으면 해당 시각에 소프트 삭제된 노드다.                                                                   | 활성 노드                                 |

## 지침 스코프

- `neo4j-memory`는 AI 에이전트 지침을 저장한다.
- 각 지침은 하나 이상의 스코프에 종속된다.

| 스코프               | 적용 범위                                                                       |
| -------------------- | ------------------------------------------------------------------------------- |
| 조직에 종속됨        | 특정 조직에 속한 모든 사용자                                                    |
| 사용자에 종속됨      | 특정 사용자                                                                     |
| PC 환경에 종속됨     | 특정 PC 환경(사용자 계정, 호스트, 셸 등. 예: `kwang@NilPark-A520M-K`, Git Bash) |
| 리포지토리에 종속됨  | 특정 리포지토리                                                                 |
| 업무 스코프에 종속됨 | 수행하는 업무의 종류                                                            |

- 모든 지침은 조직 스코프와 사용자 스코프 가운데 적어도 하나에 종속된다.
- 사용자는 조직에 소속될 수 있다.
- 스코프는 서로 겹칠 수 있다.
  - 예를 들어 지침 하나가 특정 리포지토리와 특정 PC 환경에 함께 종속된다.

## 지침 종류

- 지침은 컨텍스트 압축 뒤에 원문을 복원하는지 여부에 따라 두 종류로 나뉜다.
  - 상시 지침(`Instruction`): 세션의 스코프에 연동되어 세션 동안 유지되며, 압축 뒤에 원문이 복원된다.
  - instant 지침(`Reminder`): 대화 맥락에 따라 대화 중간에 주입되며, 압축 뒤에 원문이 복원되지 않는다.
    - 예를 들어 사용자가 "커밋해줘"라고 요청하면 "커밋 메시지는 영어로 쓴다"가 전달된다.
- 두 종류 모두 같은 스코프 규칙에 따라 스코프에 종속된다.

## 그래프 표현

- `Instruction` 노드와 `Reminder` 노드는 자신이 종속되는 각 `Scope` 노드와 관계로 연결된다.
  - 각 노드가 여러 `Scope` 노드와 연결되면, 연결된 스코프의 교집합에 종속된다.
- `Instruction` 노드는 서로 연결될 수 있다.
  - 지침을 병합할 때 순환(cycle)으로 인한 무한 반복을 방지한다.
- 대상 사이의 관계는 `Statement` 본문에 적지 않고 그래프의 관계(relationship)로 표현한다.
