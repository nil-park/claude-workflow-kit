# 0001. `-max` 계열 스킬·에이전트 본문은 한국어로 쓴다

## 배경

기존 `workflow-core`·`github-workflow`·`gitlab-workflow`의 `SKILL.md`는 본문이
영어이고, 한국어는 발동 트리거 문구와 몇몇 용어에만 섞여 있다. 반면 `docs/`와 GitHub
이슈는 한국어다.

`-max` 계열(`docs/architecture/max-plugins.md`)을 새로 만들면서 어느 쪽을 따를지
정해야 했다.

## 결정

`-max` 계열의 `SKILL.md`와 `agents/*.md` 본문을 **한국어로 쓴다.** 기존 계열은 영어
그대로 두고 바꾸지 않는다.

## 근거

판정 기준이 사용자가 읽고 직접 고치는 대상이라는 점이 결정적이다. 리뷰어들의
"본다 / 안 본다" 경계는 표현 한 줄 차이로 결과가 갈리는데, 사용자가 모국어로 읽어야
그 미세한 경계를 정확히 검토하고 고칠 수 있다.

부수적으로, `-max` 계열은 사용자와의 대화도 트리거 문구도 이미 한국어라 산출되는
리뷰 보고서도 한국어가 자연스럽다. `docs/`·이슈와 언어가 일치해 문서와 스킬 사이를
오갈 때 번역이 끼지 않는다.

## 버리는 것

- **두 계열의 언어가 갈린다.** 기존 계열과 `-max` 계열 사이에 문구를 복사할 수 없고,
  같은 기준을 두 언어로 대조 검토하기 어려워진다. 다만 두 계열은 이미 "독립이며 동기화
  장치를 두지 않는다"로 정해져 있어, 이 결정이 새로 만드는 비용은 크지 않다.
- **비한국어 사용자는 `-max` 계열을 사실상 쓸 수 없다.** `README.md`의 충돌 요소 표에
  "한국어 트리거·본문"이 이미 최상위 충돌로 올라 있으므로 새로 생긴 손실은 아니다.

모델이 영어 지시를 더 정확히 따른다는 통념은 근거로 삼지 않았다. 이 리포지토리에서
검증한 바가 없다.

## 검토한 대안

| 대안                  | 왜 안 골랐나                                                             |
| --------------------- | ------------------------------------------------------------------------ |
| 전 계열 영어 유지     | 일관되지만, 기준을 정밀하게 검토·수정해야 하는 쪽의 부담이 그대로 남는다 |
| 전 계열 한국어로 전환 | 기존 계열이 공개 마켓플레이스에 놓인 상태의 가치를 깎는다                |
| 한·영 병기            | 분량이 배가 되고, 드리프트가 생길 원천이 하나 더 늘어난다                |
