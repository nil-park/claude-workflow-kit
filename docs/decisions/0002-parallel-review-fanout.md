# 0002. 리뷰 팬아웃은 오케스트레이터-서브에이전트로 하고, 취합은 파일로 한다

## 배경

`-max` 계열([설계](../architecture/max-plugins.md))은 리뷰를 여러 축에 병렬로 흩뿌린다.
축들을 어떻게 조율하고, 라운드마다 나오는 지적을 어디에 모을지 정해야 했다.

## 결정

**조율은 오케스트레이터-서브에이전트 패턴으로 한다.** 메인이 축마다 에이전트를 띄우고,
결과를 혼자 취합한다. 에이전트끼리는 대화하지 않는다.

**취합 채널은 `.refs/` 아래 마크다운 파일로 한다.** DB도, 에이전트 간 통신 규격도 쓰지
않는다. 파일은 메인이 쓰고 에이전트는 읽기 전용으로 둔다.

## 근거

Anthropic이 정리한 [다섯 가지 조율 패턴](https://claude.com/blog/multi-agent-coordination-patterns)
중 오케스트레이터-서브에이전트가 이 문제에 가장 적은 조율 비용으로 맞아떨어진다. 리뷰
축들은 서로 독립이고 상호 의존이 거의 없어서, 에이전트끼리 발견을 주고받아야 하는 상황이
아니다.

파일을 고른 이유는 **필요한 것이 지속성뿐**이기 때문이다. 라운드를 넘어 "3라운드에서
기각한 지적"을 알아볼 수만 있으면 되고, 그 이상의 질의 능력은 쓰이지 않는다.

## 버리는 것

컨텍스트 절약을 얻지 못한다. 에이전트가 파일에 직접 쓰게 하면 메인이 안 읽어도 되겠지만,
어차피 메인이 모든 지적을 검증하느라 전부 읽어야 하므로 절약분이 없다. 대신 에이전트에게
쓰기 권한을 주지 않아 소스를 건드릴 수 없게 된다 — 이쪽을 택했다.

## 검토한 대안

| 대안                  | 왜 안 골랐나                                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SQLite 등 로컬 DB     | 라운드당 지적 수십 건 규모에 질의 능력이 필요 없다. 의존성과 스키마 관리 비용만 남는다                                                                                                           |
| Agent Teams           | 실험 기능이라 환경 변수로 켜야 하고, 서브 에이전트 정의의 `skills` 필드가 팀원에게 적용되지 않아 스킬 기반 설계가 깨진다. 세션 재개도 안 된다. 무엇보다 팀원 간 직접 대화가 필요한 문제가 아니다 |
| MCP 메시지 버스 / A2A | 조직 간·벤더 간 에이전트 연결용 규격. 한 세션 안의 독립 축 몇 개에는 과하다. ACP는 2025년 9월 A2A로 흡수됐다                                                                                     |
| 메시지 버스 패턴      | 이벤트로 워크플로가 창발하는 파이프라인용. 여기서는 단계가 처음부터 정해져 있다                                                                                                                  |
| 공유 상태(블랙보드)   | 에이전트들이 서로의 발견 위에 쌓아 올릴 때 값을 한다. 축이 독립이라 쌓아 올릴 것이 없다                                                                                                          |
