# ko-style 훅의 전제와 검증

[설계](../architecture/ko-style.md)가 딛고 선 사실과, 그것을 확인하는 방법이다.

## Stop 훅이 stdin으로 받는 것

| 필드                     | 내용                                                                         |
| ------------------------ | ---------------------------------------------------------------------------- |
| `session_id`             | 세션 식별자                                                                  |
| `prompt_id`              | 처리 중인 사용자 프롬프트의 UUID. v2.1.196 이상에서 오고 첫 입력 전에는 없다 |
| `transcript_path`        | 대화 JSONL 경로. 비동기로 쓰여 이번 턴의 마지막 메시지가 아직 없을 수 있다   |
| `cwd`                    | 훅 호출 시점의 작업 디렉터리                                                 |
| `permission_mode`        | 권한 모드                                                                    |
| `effort`                 | 이번 턴의 effort 레벨                                                        |
| `hook_event_name`        | `"Stop"`                                                                     |
| `stop_hook_active`       | 훅 때문에 이어지는 턴이면 `true`                                             |
| `last_assistant_message` | 마지막 응답 텍스트                                                           |
| `background_tasks`       | 진행 중인 백그라운드 작업                                                    |
| `session_crons`          | 세션에 걸린 예약 실행                                                        |

이번 턴에 고친 파일의 목록은 없다.

## 그 밖의 제약

- API 에러로 끝난 턴에서는 `StopFailure`가 대신 발동하고 그 출력과 종료 코드는 무시된다.
- 훅이 내보내는 문자열은 `additionalContext`를 포함해 10,000자에서 잘린다. 넘으면 파일로
  저장되고 미리보기와 경로로 대체된다.
- 훅은 탐지 결과를 Claude가 한 번 읽는 것까지만 보장한다. 지적을 읽고 아무것도 고치지 않은
  채 턴을 끝낼 수 있다.
- 사전 매칭은 앞뒤 문맥을 보지 않는다.
  - 예를 들어 `소비자`가 consumer의 직역으로 등재되어 있으면, 미국 경제를 다루는 문서에서
    `소비자`를 써도 탐지된다.
- 사전이 커질수록 오탐이 늘어난다. 탐지된 어휘는 오탐이라도 Claude가 그 자리에서 직역인지
  판단해야 하므로, 사전 크기는 그대로 매 턴의 검토 비용이 된다.
- 사전에 없는 번역투는 탐지되지 않는다. 사전은 실제로 틀렸던 것만 담는다.

## 확인하는 방법

훅 입력에 무엇이 실제로 오는지는 stdin을 그대로 파일에 쓰는 Stop 훅을 임시로 걸고 한 턴을
돌리면 나온다. 프로젝트 `.claude/settings.local.json`에 걸면 그 리포에서만 돈다.

transcript 지연은 같은 덤프에서 확인한다. 덤프한 `transcript_path`를 열어 그 턴의 마지막
`tool_use` 블록이 들어 있는지 본다.

훅 호출 비용은 스크립트 시작과 끝의 시각을 덤프에 남겨 잰다.
