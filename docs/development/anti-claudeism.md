# anti-claudeism 훅의 전제와 검증

[설계](../architecture/anti-claudeism.md)의 바탕이 되는 사실과, 그것을 확인하는 방법이다.

## Stop 훅이 받는 것

표준 입력으로 전달되는 JSON에는 다음 필드만 있다.

| 필드                     | 내용                                                                         |
| ------------------------ | ---------------------------------------------------------------------------- |
| `session_id`             | 세션 식별자                                                                  |
| `prompt_id`              | 처리 중인 사용자 프롬프트의 UUID. v2.1.196 이상에서 오고 첫 입력 전에는 없다 |
| `transcript_path`        | 대화 JSONL 경로. 비동기로 쓰여 이번 턴의 마지막 메시지가 아직 없을 수 있다   |
| `cwd`                    | 세션을 시작한 디렉터리. 프로젝트 루트라는 보장은 없다                        |
| `permission_mode`        | 권한 모드                                                                    |
| `effort`                 | 이번 턴의 effort 레벨                                                        |
| `hook_event_name`        | `"Stop"`                                                                     |
| `stop_hook_active`       | 훅 때문에 이어지는 턴이면 `true`                                             |
| `last_assistant_message` | 마지막 응답 텍스트                                                           |
| `background_tasks`       | 진행 중인 백그라운드 작업                                                    |
| `session_crons`          | 세션에 걸린 예약 실행                                                        |

**입력 JSON에는 이번 턴에 고친 파일의 목록이 없다.**

- 훅은 환경변수 `CLAUDE_PROJECT_DIR`을 받는다.
  - 이 값은 프로젝트 루트를 가리키지만, 입력 JSON의 `cwd`와 구분자가 다를 수 있다.
  - Windows에서 `CLAUDE_PROJECT_DIR`은 `C:/Git/...`, `cwd`는 `C:\Git\...`이었다.
  - 두 값을 비교하거나 상대경로를 만들 때는 정규화해야 한다.

설치본 사전의 위치는 훅 스크립트 자신의 경로로 찾는다.

## 실행 환경

- 훅은 `python3`라는 이름으로 실행된다. `settings.json`의 훅 항목에는 커맨드를 한 줄로만 적을
  수 있으므로 OS별로 실행 파일 이름을 다르게 지정할 수 없다.
  - python.org 인스톨러로 설치한 Windows에는 `python3.exe`가 없다.
  - pyenv-win과 Microsoft Store 배포판에는 `python3.exe`가 있다.
- `python3`는 3.11 이상이어야 한다.
  - 시스템의 파이썬 버전을 확인한 후 조건을 충족하지 못하면 새로 설치해야 한다.
- 파이썬의 표준 라이브러리만 사용한다.
- 훅은 리포지토리의 uv나 가상환경을 거치지 않고 시스템 `python3`로 직접 실행된다.
  - 따라서 훅은 이 리포지토리의 개발 도구와 의존성을 사용할 수 없다.
- `coding-standards`의 200줄 규칙은 훅 스크립트에 적용하지 않는다.
- Windows에서 만든 한국어 문서는 CP949로 저장되어 있을 수 있다.
- Windows에서 Python의 텍스트 stdout 기본 인코딩은 로케일 코드페이지다.
  - 한국어 Windows에서는 CP949다.
- 프로젝트의 `.python-version`은 pyenv와 uv가 사용할 Python 버전을 정한다.
  - 훅은 uv 환경을 만들지 않고 `python3`을 직접 실행한다.
  - pyenv가 `python3`을 처리하는 환경에서 지정한 버전이 없으면 훅은 실행되지 않고, 이 실패는
    표시되지 않는다.

## 플랫폼이 정한 것

- API 에러로 끝난 턴에서는 `StopFailure`가 대신 발동하고 출력과 종료 코드는 무시된다.
- Claude Code는 훅이 stdout으로 내보낸 바이트를 UTF-8로 해석한다.
  - 훅 문서에는 인코딩 규정이 없으며, 이 동작은 실측으로 확인했다.
  - 해석하지 못한 바이트는 U+FFFD로 대체되고 JSON 파싱은 성공한다.
  - CP949로 출력하면 오류 없이 한글이 U+FFFD로 대체된 보고가 도착한다.
- 훅이 내보내는 문자열은 `additionalContext`를 포함해 10,000자에서 잘린다.
  - 10,000자를 초과하면 파일로 저장되고 미리보기와 경로로 대체된다.
- Claude Code는 훅이 8회 연속으로 막으면 무시하고 턴을 끝낸다. 이 훅은 두 번째 Stop을
  통과시키므로 그 상한까지 가지 않는다.
- 훅은 탐지 결과를 Claude가 한 번 읽는 것까지만 보장한다. 지적을 읽고 아무것도 고치지 않은
  채 턴을 끝낼 수 있다.
- Bash로 고친 파일은 탐지되지 않는다. `tool_use` 입력에 경로가 없고 명령 문자열만 있다.
  - `sed -i`, `cat > f <<EOF`, 스크립트가 안에서 쓰는 파일이 모두 여기 해당한다. 그 파일을
    나중에 `Write`나 `Edit`으로 건드리면 그때 검사된다.
  - 검사를 건너뛴 것을 알리는 신호는 없다. 오류도 경고도 나지 않아 탐지 결과가 없는 턴과
    구별되지 않는다.
- auto mode는 시스템 프롬프트로 "make file changes with sed, heredocs, or short scripts,
  rather than using the dedicated Read, Edit, or Write tools"를 주입한다. 그 모드에서는 편집이
  Bash로 가므로 이 훅이 사실상 실행되지 않는다.
  - 읽기와 검색에 쓰는 `cat`, `grep`, `find`는 훅이 보는 도구가 아니어서 아무 영향이 없다.

## 탐지의 한계

- 1MB를 넘는 파일은 검사되지 않는다. 사람이 읽는 문서는 그만큼 커지지 않는다.
- `claudeism-dictionary.json`이나 `test_anti_claudeism.py`라는 이름을 쓰는 파일은 검사되지 않는다.
- `anti-claudeism` 스킬 본문은 틀린 표현을 예시로 그대로 담으므로, 본문을 고친 턴에는
  예시로 적은 줄이 탐지된다. 탐지된 것은 모두 의도한 표현이다.
- 사전 매칭은 앞뒤 문맥을 보지 않는다.
  - 예를 들어 `소비자`가 consumer의 직역으로 등재되어 있으면, 미국 경제를 다루는 문서에서
    `소비자`를 써도 탐지된다.
- 사전이 커질수록 오탐이 늘어난다. 탐지된 표현은 오탐이라도 Claude가 그 자리에서 직역인지
  판단해야 하므로, 사전 크기는 그대로 매 턴의 검토 비용이 된다.
- 사전에 없는 표현은 탐지되지 않는다. 사전은 실제로 틀렸던 것만 담는다.
- 스킬과 함께 설치되는 사전은 갱신될 때 통째로 교체된다. 거기에 직접 적은 것은 남지
  않는다. `anti-claudeism` 스킬 본문도 같아서, 설치된 사본에 예시를 보태 봐야 다음 갱신에
  사라진다. 사전과 예시를 늘리는 것은 이 리포에서 할 일이다.
- `term`이 짧을수록 다른 단어에 파묻힌다. 경계를 걸지 않으면 `축`은 `축소`·`건축`·`압축`에
  전부 걸린다.
- 용언은 어간과 어미가 한 음절로 합쳐져서 어절 경계를 걸 수 없다.
  - `되어지다`는 `되어진다`에서 `되어진`, `되어졌다`에서 `되어졌`이 된다. 공통 접두는
    `되어`뿐이고, 그것은 `되어서`·`되어야`에도 걸린다.
- 이중 피동이라고 다 틀린 것은 아니다. `알려지다`, `밝혀지다`, `이루어지다`는 표준이다.
  `-어지다`로 끝나는 말을 한꺼번에 잡으면 이것들까지 탐지되므로, 틀린 것을 하나씩 등재한다.

## 전제 검증 방법

- Stop 훅이 stdin으로 받는 JSON 필드 표를 확인한다.
  - stdin을 그대로 파일에 쓰는 훅을 임시로 걸고 한 턴을 실행해 표를 얻는다.
  - 표를 다시 확인할 때도 같은 방법을 쓴다.
  - 프로젝트 `.claude/settings.local.json`에 훅을 등록하면 해당 리포지토리에서만 실행된다.
- 훅을 등록한 뒤 `/hooks`로 등록 상태를 먼저 확인한다.
  - `0 hooks configured`로 나오면 해당 세션은 훅을 인식하지 못한 것이다.
  - 이때는 `claude --resume`으로 세션을 다시 연다.
  - 세션 도중에 `.claude/settings.local.json`을 새로 만든 경우가 여기에 해당한다.
  - 훅 문서에는 설정 파일의 훅을 고치면 파일 감시자가 변경을 감지한다고 되어 있다.
    그러나 없던 설정 파일을 새로 만드는 변경은 감지하지 못했다.
  - 훅이 실행되지 않아도 겉으로 드러나지 않으므로, 등록 상태를 확인하기 전에는 측정 결과를
    믿지 않는다.
- transcript 지연은 [0001](../decisions/anti-claudeism/0001-transcript-lag.md)에서 측정했다.
  - 다시 측정할 때는 기록된 `transcript_path`를 1초 간격으로 두 번 읽는다.
  - 두 번 읽은 편집 목록과 파일 크기를 비교한다.
- stdout 인코딩은 같은 한글을 UTF-8 바이트와 cp949 바이트로 한 문자열에 나란히 담아 보낸다.
  - Claude Code가 받은 문자열의 코드포인트를 후보 디코딩 결과와 비교한다.
  - ASCII만 담은 대조군을 먼저 보내 훅이 실제로 연결되었는지 확인한다.
- 훅 호출 비용은 훅과 인터프리터의 기동 비용을 나누어 측정한다.
  - 훅을 하위 프로세스로 여러 번 실행하고 실제 경과 시간을 측정한다.
  - 같은 횟수로 인터프리터만 실행해 기동 시간을 따로 측정한다.
  - 훅은 파일 전체를 읽고 사전의 모든 정규식을 적용하므로, 검사 시간은 파일 크기와 사전
    항목 수의 영향을 받는다.
  - 탐지 건수가 많으면 각 결과의 줄 번호를 계산하고 정렬하는 비용도 늘어난다.
    줄마다 표현이 탐지되는 파일을 만들어 이 비용도 함께 측정한다.
