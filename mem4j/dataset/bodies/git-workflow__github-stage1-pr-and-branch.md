- **내가 명시적으로 "설계만" 또는 "구현만"이라고 지정하지 않는 한, PR은 설계와 구현을 모두 포함한다.**
- **브랜치를 만들기 전에 origin의 기본 브랜치(main/master)를 확인한다.**
  - PR은 이 기본 브랜치를 대상으로 연다.
- 브랜치를 만들어 push한다.
  - **리포지토리에 브랜치 이름 관례가 있으면 그것을 따른다.**
    - 브랜치가 적어 관례를 판단할 수 없으면 아래 기본값을 제안하고 확인받는다.
  - 관례가 없으면 기본값인 `<타입>/<이슈번호>-<슬러그>`로 짓는다(예: `chore/47-add-user-ssh-key`).
    - 이슈가 없으면 이름에서 번호를 생략한다.
